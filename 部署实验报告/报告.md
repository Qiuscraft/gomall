# 自动扩缩容实验

在 [user.yaml](vscode-file://vscode-app/d:/OfficeApps/Microsoft VS Code/resources/app/out/vs/code/electron-browser/workbench/workbench.html) 给 `user` Deployment 加上 `resources` 配置（CPU 请求 100m、内存请求 128Mi，限制 500m/256Mi），满足 HPA 对资源指标的前提；新增了 [user-hpa.yaml](vscode-file://vscode-app/d:/OfficeApps/Microsoft VS Code/resources/app/out/vs/code/electron-browser/workbench/workbench.html)，定义基于 CPU 利用率的自动扩缩容策略（1~5 副本，目标 60%）。（总共实现了三个微服务的扩缩容）

证明：

重新应用更新后的 Deployment 与新增 HPA：

```
kubectl apply -n gomall-middlewares -f k8s/apps/user.yaml

kubectl apply -n gomall-middlewares -f k8s/apps/user-hpa.yaml
```

然后确认：

kubectl get deploy/user -n gomall-middlewares -o wide

kubectl get hpa/user -n gomall-middlewares

- 验证自动扩缩容：

  1. 读取 HPA 状态是否 `AbleToScale/ScalingActive`；

  2. 制造 CPU 压力，例如在userPod 里运行一个dd或yes命令：

     ```
     kubectl exec -n gomall-middlewares deploy/user -- \
      sh -c "yes > /dev/null"
     ```

  3. （保持一段时间，观察 HPA 指标变化后 kubectl get hpa -w 查看CURRENT利用率和DESIRED 副本数）；

  4. 当 HPA 判定 CPU 超标时会把 `user` 副本数扩容到 2 或更多；停止负载（Ctrl+C 后 `kubectl exec` 自动退出），再观察副本数回落。

可以看到自动扩容：

![屏幕截图 2025-12-07 202547](E:\VscodeProjects\gomall\部署实验报告\屏幕截图 2025-12-07 202547.png)

停止进程（或删除pod）然后等待5min，回落，证明缩容：

注意：

- HPA 已经看到 `cpu: 1%/60%`，说明指标满足缩容条件；之所以还保持 5 副本，是因为默认的 scaleDown 稳定窗口是 300 秒（5 分钟）。HPA 会在距离上一次扩容或缩容动作超过 5 分钟后才真正把副本数降下来，所以再等几分钟就会自动回落到 1。
